# AI Automation Bridge 对接协议

**版本**: V4.6 协议版
**协议版本**: `1.1`
**面向**: 前端开发同事（外部 iframe 内系统接入方）
**用途**: 直接对接浏览器宿主与 iframe 内业务系统的消息协议

---

## 1. 协议总览

### 1.1 消息方向

- iframe -> 宿主：发送 `request`
- 宿主 -> iframe：返回 `response`
- 宿主 -> iframe：主动推送 `event`

### 1.2 元素定位约定

```text
target_ref > selector
```

- `target_ref`：首选元素引用，适合后续连续操作
- `selector`：适合首次定位

### 1.3 最常用调用链

```typescript
const resolved = await bridge.call('resolve_selector', {
  selector: '#submit',
  selector_type: 'css',
});

await bridge.call('click_button', {
  target_ref: resolved.target_ref,
});
```

## 2. 通用消息结构

```typescript
export enum MessageType {
  REQUEST = 'request',
  RESPONSE = 'response',
  EVENT = 'event',
}

export interface BridgeError {
  code: ErrorCode;
  message: string;
  detail?: any;
}

export interface Message {
  id: string;
  type: MessageType;
  command?: string;
  payload?: any;
  error?: BridgeError;
  timestamp: number;
  manifest_version?: string;
}
```

### 2.1 请求示例

```typescript
window.parent.postMessage({
  id: 'req_1',
  type: 'request',
  command: 'navigate',
  payload: {url: 'https://example.com'},
  timestamp: Date.now(),
}, window.location.origin);
```

### 2.2 响应示例

```typescript
{
  id: 'req_1',
  type: 'response',
  command: 'navigate',
  payload: {
    success: true,
    url: 'https://example.com',
  },
  timestamp: Date.now(),
}
```

## 9. 常用错误码

```typescript
export enum ErrorCode {
  INVALID_COMMAND = 'INVALID_COMMAND',
  INVALID_PAYLOAD = 'INVALID_PAYLOAD',
  EXEC_ERROR = 'EXEC_ERROR',
  TIMEOUT = 'TIMEOUT',
  INVALID_ORIGIN = 'INVALID_ORIGIN',
  PROTOCOL_ERROR = 'PROTOCOL_ERROR',
  MANIFEST_STALE = 'MANIFEST_STALE',
  TARGET_STALE = 'TARGET_STALE',
  CANCELLED = 'CANCELLED',
  ERR_NOT_IMPLEMENTED = 'ERR_NOT_IMPLEMENTED',
  NO_ACTIVE_PLAN = 'NO_ACTIVE_PLAN',
}
```

常见含义：

- `TARGET_STALE`：之前拿到的 `target_ref` 已失效
- `MANIFEST_STALE`：页面已变化，当前 `manifest_version` 过期
- `INVALID_PAYLOAD`：请求参数缺失或类型不对
- `EXEC_ERROR`：执行失败
- `TIMEOUT`：执行超时
- `NO_ACTIVE_PLAN`：调用 `skip_step` / `stop_plan` 时无活跃计划

## 10. 最小接入建议

- 初始化后先监听 `event`
- 收到 `manifest_push` / `manifest_update` 后缓存 `manifest_version`
- 需要稳定操作同一元素时，先调 `resolve_selector`，后续一律使用 `target_ref`
- 涉及页面语义工具时，优先使用 `discover_tools` 返回的 `target_ref`
- 收到 `confirm_required` 时，必须回 `confirm_response`
- 长时间计划建议配合 `plan_progress.step_result` 实时展示步骤状态
- 需要人工介入时使用 `skip_step` / `stop_plan` 中断计划
- 机械恢复型失败（元素未渲染、下拉列表不可见）可在 step 设置 `recovery` + `max_retries`，由浏览器侧自动闭环
