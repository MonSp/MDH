# MDH 演进：人+agent 混合团队协作平台（办公垂直）设计

> 产品定义头脑风暴产物（2026-08-14）。基于两份研究：`multi-agent-architecture-future-analysis.md`（行业方向 43 来源）与 `deepseek-harness-code-principles.md`（dsh 全库 104 条原理）。本设计经用户逐节确认。

## [S1] 产品定位与价值主张

MDH 从"多智能体协作平台"演进为 **"人+agent 混合团队协作平台"（办公垂直）**：部门员工与各自的 work agent 组成混合团队，完成文档型任务，过程中沉淀组织资产。

**双内核并列、互相强化**：
- **编排内核**：需求进来 → 混合团队（人 + agent）动态组队 → 并行派发 → 员工关键把关 → 交付
- **资产内核**：三类资产沉淀——产出物（知识库）、模板（优质交付固化）、经验技能（agent 越用越会干活）

**产品决策（已逐项确认）**：
| 维度 | 决策 |
|---|---|
| 产品内核 | 双内核并列（编排 + 资产互相强化） |
| 编排对象 | 混合：自有 agent 为主 + 第三方协议接入（MVP 不做第三方） |
| 目标用户 | B2B 公司/团队切入 |
| 人的参与 | 关键把关：人管决策点，agent 管执行 |
| 与现有 MDH | 定位演进：现有五支柱为引擎层，叙事升级 |
| 垂直场景 | 文职/办公垂直，文档型任务为主 |
| 需求形态 | 平台内提交，文档型任务（可验证交付物） |
| 知识沉淀 | 三类资产：产出物 + 模板 + 经验技能 |
| 组织边界 | 团队/部门级起，部门内闭环 |
| 成功标准 | 单一部门试点跑通闭环（3 个月，50%+ 纪要任务走平台） |
| 演进路线 | 场景优先：先跑通 1-2 个高频文档任务 |

## [S2] 试点场景与全链路

**首场景：会议纪要 + 待办**。理由：高频、低风险、交付物可验证（纪要 + 待办清单 + 邮件分发）、跨部门通用、天然展示"关键把关"与"知识沉淀"。

**试点范围**：一个部门（市场/行政/运营，10-20 人），3 个月闭环。

**全链路数据流**：
```
1. 需求进入   员工/领导提交（上传速记/录音转写）→ 意图识别判为「会议纪要+待办」任务
2. 混合组队   TeamAssembler 组装：执行 agent{纪要撰写员, 待办提取员} + 把关人{提交者, 部门负责人*}
3. DAG 执行   提取要点/决策/行动项 → 撰写纪要初稿+待办清单(docx) → 校对(遗漏/冲突检查, 规则+LLM)
4. 员工把关   提交者收把关请求 → 修改/通过 → 确认分发范围          (*关键节点审批复用 ApprovalManager)
5. 分发       邮件/IM 分发（适配器），分发记录入日志
6. 沉淀       产出物入库(知识库) · 优质纪要固化为模板(需员工确认) · 把关修改差异提炼经验规则→技能 CoW 增量
7. 资产复用   下次同类任务：意图识别时检索知识库/模板/技能注入（复用经验注入机制）
```

**错误处理与边界**：
- 把关超时：文档任务低危，沿用审批超时语义（超时默认通过 + 记录，可配置改为挂起提醒）
- 速记质量差（转写混乱）→ 意图识别置信度低 → 降级为人工模式（提交者自填纪要骨架，agent 润色）
- 分发失败 → 复用 `fallback_chain` 重试 + 通知
- 资产去重/权限：知识库团队级隔离；模板沉淀必须员工确认；技能增量沿用 `source_task_id` 项目隔离防污染

## [S3] 架构：五支柱映射与演进增量

现有五支柱 = 新平台引擎层，直接映射，无需重写：

| 现有支柱 | 演进后角色 |
|---|---|
| 意图识别拆解 | 需求拆解：速记 → {纪要, 待办, 分发} 子任务 |
| 动态团队组装 | 混合团队组装：成员可为"人"（把关）或"agent"（执行） |
| 并行执行（DAG） | 文档任务流水线：提取 → 撰写 → 校对 → 分发 |
| 审查把控 | 员工把关点：纪要确认 / 待办优先级确认 / 分发确认 |
| 技能随用随进化 | 组织知识沉淀：纪要模板 + 写作技能 + 知识库（CoW 复用） |

**演进新增 5 个组件**（增量，非重写）：
1. **员工身份与把关点引擎**——人成为第一等实体；`ApprovalManager` 升级为把关点引擎（决策节点挂人，`human_approval_request` 语义复用；把关决定 = durable 事件，重放即状态）
2. **团队知识库**——三类资产统一存储，与 `skill_packs` CoW 增量机制打通
3. **文档工具集**——离线 docx 生成（复用 `offline-docx-generation` 设计）+ 纪要结构化渲染 + 邮件/IM 分发适配器
4. **混合团队组装器**——`TeamAssembler` 扩展成员类型 `human | agent`；agent 侧沿用 role 模板 + location（本地/远端）；预留第三方协议适配器位（仿 dsh subagent transport 注册表，MVP 不实现）
5. **文档型意图识别**——`SemanticAnalyzer` 增加文档任务模式：速记文本 → 结构化任务拆解（确定性规则 + LLM 兜底，沿用两层判定）

## [S4] 关键机制（dsh 研究落地）

| dsh 原理 | 落地 |
|---|---|
| session log 真相源（P-1.3/1.6） | 混合团队协作记录 = append-only 事件日志（提交/执行/把关/修改）；模型上下文从 log 投影；组织记忆底层 = 日志 + 知识库，可重放可审计 |
| 审批=日志折叠（P-9.1/9.2） | 把关策略与决定为 durable 事件（重放即状态）；把关请求/决定成对审计，异常路径归一拒绝 |
| subagent 委托语义（P-2.1/2.8） | 每个执行 agent 是独立 Session（descriptor 持久化、可续跑/恢复）；员工是"把关节点"而非 agent，共享同一团队事件流 |
| 技能渐进披露（P-5.11） | 知识库/模板/技能对执行 agent 只给摘要目录 + 按需加载全文 |
| capability seam（P-4.1） | 文档工具集（docx 渲染/分发/速记解析）做成 seam：定义/provider（本地/远端）/consumer |
| 上下文溢出 spill（P-9.9） | 长速记文本、长文档输出 spill 到文件，模型只留摘要 + 定位（文职场景必选） |

**MVP 取舍**：第三方个人 agent 接入不做（适配器位预留）；不做公司级多租户；不做实时录音转写（先接人工粘贴速记文本）。

## [S5] 测试、验证与里程碑

**测试策略**（沿用 MDH 基线 backend pytest + orchestrator/前端 vitest）：
- 新增测试点：文档意图识别模式判定、混合团队组装（human/agent）、把关点引擎（审批语义复用 + 日志折叠断言）、沉淀闭环（入库/模板固化/技能增量 + 项目隔离）、文档工具 seam（docx 渲染一致性）
- 借鉴 dsh 工程纪律：文档任务全链路录制/回放（P-10.1）——录制真实任务会话 → 无 key 回放验证

**里程碑（单部门 3 个月试点）**：
| 阶段 | 范围 | 验收 |
|---|---|---|
| M1（1-4 周） | 引擎底座：员工身份 + 把关点引擎、混合团队组装（human/agent）、文档工具 seam（docx 生成） | 单测 + 集成测试绿；API 可演示组队与把关 |
| M2（5-8 周） | 会议纪要全链路：文档意图识别、DAG 流水线（提取→撰写→校对）、把关 UI、邮件分发适配器 | 试点部门真实纪要任务跑通，员工把关闭环 |
| M3（9-12 周） | 沉淀闭环：知识库入库、模板固化（员工确认）、技能进化（把关差异提炼）、资产复用注入 | 试点部门 50%+ 纪要任务走平台；资产复用率可感知 |

**非目标（本期不做）**：第三方 agent 接入、公司级多租户、实时录音转写、IM 深度集成（先邮件分发）。
