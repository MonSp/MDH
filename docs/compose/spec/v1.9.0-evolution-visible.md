# v1.9.0 — 进化可见 + LLM 提炼 + 前端治理

## [S1] Problem

MDH 的进化系统后端极其完整（7 层管线、1100+ 行 extractor、42 技能树、10 部门职业路径），但用户几乎无法感知"数字员工在变强"：

1. **进化不可见**：进化面板埋在 Meeting Panel 的 Skills 子标签；XP 数字是静态卡片不是叙事；CapabilityBoundary、ReflectionPriority、规则进化链完全没有前端暴露；没有"同一任务类型注入前 vs 后"的成功率证明。
2. **提取是瓶颈**：经验规则完全靠字符串模板拼接（截断任务描述 + 关键词 bigram），规则进化只是在低分规则后追加括号注释。没有 LLM 参与，"越用越强"的实际效果受限。
3. **前端技术债务**：~130 处 fetch 直调未用统一 apiClient；大量内联样式无 CSS 模块；~20 个 3D 装饰组件未懒加载。

## [S2] Design

### S2.1 进化事件流系统

后端新增进化事件模型，记录每次进化相关的状态变化：

```
EvolutionEvent:
  event_id: str
  event_type: "xp_granted" | "skill_level_up" | "career_promotion" | "rule_created" | "rule_evolved" | "rule_demoted" | "rule_approved" | "domain_confidence_change"
  agent_id: str
  timestamp: str
  details: Dict  # event-type-specific payload
  task_id: str   # related task (optional)
  before_state: Dict  # snapshot before change
  after_state: Dict   # snapshot after change
```

事件在以下时机产生：
- `agent_profile_manager.grant_xp()` → `xp_granted` + 可能触发 `skill_level_up` / `career_promotion`
- `experience_extractor._save_rule()` → `rule_created` / `rule_evolved`
- `experience_extractor.approve_rule()` → `rule_approved`
- `experience_extractor.reject_rule()` / auto-demotion → `rule_demoted`
- `capability_boundary.detect_unknown_domain()` → `domain_confidence_change`

存储：SQLite `evolution_events` 表（agent_id, event_type, timestamp, details JSON, task_id, before_state JSON, after_state JSON），带 agent_id + timestamp 复合索引。

API:
- `GET /api/evolution/timeline?agent_id=&event_type=&since=&limit=50` → 分页事件流
- `GET /api/evolution/timeline/summary?agent_id=&period=7d` → 聚合统计（XP 增量、规则变化数、晋升次数）

前端 `EvolutionTimelinePanel` 组件：可交互时间线，按事件类型着色，支持 agent 过滤和时间范围选择。展示为垂直时间线，每个事件节点可展开查看详情。

### S2.2 规则进化链可视化

后端已有 `get_evolution_chain(rule_id)` 返回 parent→child 链。

新增 API：
- `GET /api/experience/rules/{rule_id}/chain` → 完整进化链（含每代 effectiveness_score、usage_count、status）

前端 `RuleLineageView` 组件：以树形/流程图展示规则的进化历程。每个节点显示规则摘要 + effectiveness + status。从"失败任务"到"成功规则"的叙事路径。

### S2.3 能力边界可视化

后端已有 `capability_boundary.compute_confidence_map()` 返回每个领域的置信度。

新增 API：
- `GET /api/agents/{agent_id}/capability-map` → 各领域置信度
- `GET /api/agents/{agent_id}/capability-map/confidence/{domain}` → 单领域详情

前端 `CapabilityRadarChart` 组件：雷达图展示 agent 在各领域的置信度。低于阈值的领域标红。集成到 AgentProfilePanel。

### S2.4 A/B 进化证明

后端新增任务类型级成功率追踪：

```
ABTracker:
  # 按 (task_type, period) 追踪成功率
  # period: 7d rolling window
  # 对比: 有规则注入 vs 无规则注入的成功率差异
```

存储：SQLite `task_type_performance` 表（task_type, period_start, total_tasks, tasks_with_rules, success_with_rules, success_without_rules）。

在 `a2a_post_processor.process()` 和 `simple_executor.execute()` 的成功/失败路径中更新统计数据。

API：
- `GET /api/evolution/ab-stats?task_type=&period=30d` → A/B 对比数据

前端 `EvolutionProofCard` 组件：显示"有规则注入 vs 无规则注入"的成功率对比，用条形图直观展示"越用越强"的证据。集成到 PerformanceDashboard。

### S2.5 LLM 经验提炼

改造 `experience_extractor.extract_from_meeting()` 和 `extract_from_success()` 的核心提取逻辑：

**改造前**（模板提取）：
```
trigger_condition = f"human_feedback for task type: {task_description[:50]}"
action = suggestion.strip()
```

**改造后**（LLM 提炼 + 模板 fallback）：
```
def _llm_distill(self, task_description, result_text, context) -> List[Dict]:
    """调用 LLM 从执行结果中提炼通用经验规则"""
    prompt = f"""从以下任务执行中提炼可复用的经验规则。
    
任务描述: {task_description}
执行结果: {result_text[:2000]}
上下文: {context}

输出 JSON 数组，每条规则包含:
- trigger_condition: 何时应用此规则（通用描述，不包含特定任务细节）
- action: 具体建议动作
- rule_type: success_pattern | failure_avoidance | correction_tip
- keywords: [相关关键词]

要求: 规则必须可跨任务复用，不能包含特定任务ID或文件名。"""
    
    # 调用 DeepSeek via existing LLM 路由
    response = await self._llm_call(prompt)
    return parse_rules_from_response(response)
```

- 使用 DeepSeek（复用现有集成）
- LLM 不可用或超时时自动降级到模板提取
- LLM 产生的规则标记 `source: "llm_distill"`，模板产生的标记 `source: "template"`
- 后续可按 source 对比规则质量

### S2.6 前端治理

**S2.6.1 统一 apiClient**
新建 `src/utils/apiClient.ts` 统一模块（扩展现有 `apiFetch`）：
- 统一错误处理（toast 通知 + 重试逻辑）
- 统一超时配置
- 统一认证 token 注入
- 迁移 ~130 处 `fetch('/api/...')` 调用

**S2.6.2 进化面板提升为顶级入口**
- `SkillEvolutionDashboard` 从 Meeting Panel 的 Skills 标签提升为 AppHeader 级别的独立入口
- 新增 Evolution Timeline tab（S2.1）
- 新增 Rule Lineage tab（S2.2）
- 新增 A/B Proof tab（S2.4）
- 新增 Capability Radar tab（S2.3）

**S2.6.3 3D 组件懒加载**
- Cyberpunk 3D 组件（~20 文件）改为 `React.lazy()` + `Suspense`
- 首屏只加载 OfficeScene 骨架，3D 内容异步加载

**S2.6.4 CSS 模块化**
- 新建组件使用 CSS Modules（`.module.css`）
- 存量组件逐步迁移（本次至少迁移进化相关的新组件）

## [S3] Out of Scope

- Electron 端适配（不在本次范围）
- 英语国际化（i18n 不在本次范围）
- 存量组件的 CSS 模块全面迁移（只迁移新组件 + 进化面板）
- 向量数据库 / 语义嵌入检索（关键词匹配仍是主路径）
- 多 LLM 提供商可配置（固定 DeepSeek）
