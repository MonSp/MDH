# v0.3.0 — 可观测性栈 (Prometheus + Grafana)

## [S1] Problem

MDH 有 15 个子系统在运行，内部指标收集器（metricsCollector.ts、proactive_monitor.py、performance_dashboard.py）已经采集数据，但这些数据没有任何外部可见性。生产事故无法被检测、诊断或告警。这是当前最大的运营风险。

## [S2] Design

### S2.1 Prometheus 接入

**目标**：将后端已有的 Prometheus `/metrics` 端点接入真正的 Prometheus 实例。

**实现**：
1. `docker-compose.yml` 添加 `prometheus` 服务
2. `prometheus.yml` 配置文件：抓取 backend:8765/metrics，30s 间隔
3. 确保 `/metrics` 端点输出格式正确的 Prometheus 指标（检查现有实现）

**已有指标**（需验证格式）：
- `mdh_a2a_agents_active` — 活跃 A2A 节点数
- `mdh_a2a_tasks_total` — A2A 任务总数
- `mdh_a2a_task_duration_avg_seconds` — A2A 平均任务耗时
- `mdh_requests_total` — 请求总数
- `mdh_request_duration_seconds` — 请求耗时

**需新增指标**：
- `mdh_llm_calls_total{provider,model,status}` — LLM 调用计数
- `mdh_llm_tokens_total{provider,model,direction}` — Token 消耗
- `mdh_llm_cache_hits_total` — 缓存命中
- `mdh_llm_cache_misses_total` — 缓存未命中
- `mdh_task_success_total{task_type}` — 按任务类型的成功计数
- `mdh_task_failure_total{task_type}` — 按任务类型的失败计数
- `mdh_evolution_events_total{event_type}` — 进化事件计数
- `mdh_xp_granted_total` — XP 授予总量
- `mdh_skill_level_ups_total` — 技能升级次数
- `mdh_ws_connections_active` — 活跃 WS 连接数
- `mdh_ws_messages_total{direction}` — WS 消息总数

### S2.2 Grafana 接入

**目标**：4 个预配置仪表盘，JSON provisioning。

**实现**：
1. `docker-compose.yml` 添加 `grafana` 服务
2. `grafana/provisioning/datasources/prometheus.yml` — 自动配置 Prometheus 数据源
3. `grafana/provisioning/dashboards/` — 4 个 JSON 仪表盘文件

**仪表盘 1：后端健康**
- 面板：请求 QPS、P50/P95/P99 延迟、错误率、健康检查状态
- 面板：活跃 WebSocket 连接数、消息吞吐量
- 告警：错误率 > 5% 持续 2 分钟、P99 延迟 > 10s

**仪表盘 2：Agent 性能**
- 面板：任务成功率趋势（按 task_type 分组）、XP 授予趋势
- 面板：技能升级事件时间线、晋升事件时间线
- 面板：进化事件类型分布（饼图）
- 告警：任务成功率 < 70% 持续 5 分钟

**仪表盘 3：LLM 成本**
- 面板：LLM 调用次数（按 provider 分组）、Token 消耗趋势
- 面板：缓存命中率、提供商分布（饼图）
- 面板：单次调用平均 token 数、估算成本
- 告警：单小时 token 消耗超过阈值

**仪表盘 4：路由准确率**
- 面板：A2A 节点活跃数、任务分布（本地 vs A2A）
- 面板：部门路由命中率、成功率对比
- 面板：A2A 节点健康状态、心跳延迟
- 告警：A2A 节点全部离线

### S2.3 指标收集增强

**backend/metrics_collector.py**（新增 Prometheus 指标）：
- 在现有指标收集基础上，注册 Prometheus Counter/Gauge/Histogram
- 使用 `prometheus_client` 库（标准 Python Prometheus 客户端）
- 在关键路径插入指标更新：LLM 调用、任务完成、进化事件、XP 授予、WS 消息

**前端指标**（已有 `metricsCollector.ts`）：
- 前端指标通过 `/api/metrics` 端点暴露给 Prometheus（pull 模式）
- 或者前端通过 WS 推送指标到后端（push 模式）
- 选择 pull 模式：前端指标聚合后暴露在 `/metrics` 端点

### S2.4 告警规则

**prometheus/alerts.yml**：
- 后端不可用：health 端点连续 3 次失败
- 高错误率：5xx 错误率 > 5% 持续 2 分钟
- 高延迟：P99 > 10s 持续 5 分钟
- LLM 故障：LLM 调用失败率 > 20% 持续 3 分钟
- A2A 节点全离线：活跃节点数 = 0 持续 5 分钟
- 任务成功率低：成功率 < 70% 持续 5 分钟
- 磁盘空间：data 卷使用率 > 80%

## [S3] Out of Scope

- Sentry 错误追踪（单独版本）
- 分布式追踪（Jaeger/Zipkin）
- 日志聚合（ELK/Loki）
- 告警通知渠道（Slack/邮件/PagerDuty）— 只做规则，不做通知路由
- 前端性能监控（Core Web Vitals）
