# MDH 大荒界 · 产品故事

## 一句话

**AI agent 不应该是工具，而应该是员工——它们会工作、会犯错、会学习、会成长，最终成为比你更懂业务的同事。**

---

## 起点：一个反直觉的观察

2024 年，每家公司都在用 AI。但用法都一样：开一个对话框，问一个问题，得到一个回答，关掉。下次再问，它什么都不记得。

这就像每天早上新招一个员工，晚上辞退，第二天再招一个。

没有人会这样管理团队。但所有人都是这样用 AI 的。

**MDH 的起点就是这个问题：如果 AI agent 有记忆、有经验、有职业发展，会发生什么？**

---

## 第一幕：数字员工（MDH-Company）

MDH-Company 是一个数字员工操作系统。

你不是在"用 AI"，你是在"管理一个 AI 团队"。

你派一个任务——"分析代码质量并给出改进建议"。CEO agent 拆解需求，组建团队：架构师负责方案设计，开发负责代码审查，QA 负责验证。它们在 3D 虚拟办公室里开会、讨论、投票、执行。

任务完成后，三件事发生：

1. **产出物入库**——代码审查报告变成可复用的资产
2. **经验提炼**——"在 Python 项目中先检查类型注解再检查逻辑"这条规则被写入技能包
3. **XP 增长**——架构师的 `architecture` 技能从初级升到中级

下次再接到类似任务，系统自动检索最相关的历史经验注入上下文。踩过的坑不会再踩。

**这不是 prompt engineering，这是 knowledge management。**

### 进化闭环

```
任务 → 执行 → 产出资产 → 提炼经验 → 技能进化 → 下一次更高效
```

但经验不是只增不减。每条规则都有有效性评分——注入后任务成功 +1，失败 -1。连续 3 次以上成功率低于 40% 的规则自动降级退回审核。坏经验被淘汰，好经验留下来。

数字员工有了免疫系统。

42 个技能覆盖工程、设计、内容、数据、管理五大类别，组成依赖树。10 个部门各有独立的晋升路径。高级员工做简单任务时 XP 衰减——必须承担真正有挑战的工作才能成长。

**在 MDH 里，"AI 幻觉"不是 bug，是需要被纠正的错误认知——而系统会自动纠正它。**

## 第二幕：虚拟世界（MDH-Game）

如果数字员工有技能、有记忆、有性格——它们在虚拟世界里会是什么样子？

MDH-Game（太古纪元：霸业）回答了这个问题。

这是一个 2.5D 像素风修仙 MMORPG。但 NPC 不是写死的脚本，而是由 agent-kernel 驱动的智能体——它们和 Company 里的数字员工是同一批"人"。

Company 里的「高级后端工程师」，在 Game 里是「元婴期阵法师」。
Company 里的「QA 专家」，在 Game 里是「金丹期试炼者」。

**技能映射：**

| Company 视角 | Game 视角 | 同一份数据 |
|---|---|---|
| `backend_dev` (后端开发) | `阵法` (阵法造诣) | 同一个 skill_id |
| `ml_engineering` (机器学习) | `炼丹` (炼丹术) | 同一个 skill_id |
| `security_audit` (安全审计) | `禁制` (禁制术) | 同一个 skill_id |
| `testing` (测试) | `试炼` (试炼术) | 同一个 skill_id |

NPC 有自己的性格（6 维模型：野心/谨慎/忠诚/贪婪/社交/勤勉），有三级记忆系统（短期交互→中期摘要→长期里程碑），有行为树驱动的日常活动。

它们会记住被谁欺负过，会传播八卦（传闻系统，每传一次可信度衰减），会在渡劫时紧张，在被赠予丹药时开心。

**在 Game 里，NPC 不是背景板——它们是活的。**

## 第三幕：内核（agent-kernel）

两个产品，一套灵魂。

agent-kernel 是一个独立的 C++ ECS（实体-组件-系统）引擎，以 Unix Socket + JSON 协议对外提供服务。

**为什么是 C++ ECS？**

- **性能**：slot-based 存储，支持 100K+ entity，单帧遍历全部 agent 的内存开销极低
- **灵活性**：组件可选挂载，Game 的 NPC 多挂战斗/位置组件，Company 的 agent 多挂任务/资产组件
- **统一性**：同一个 agent entity 在两个产品间共享，数据只有一份

**9 个通用组件：**

```
Identity    · 身份（名称/部门/角色）
Stats       · 属性（XP/职级/力量）
Personality · 6 维性格模型
Memory      · 三级记忆（短/中/长期 + 传闻）
Lifecycle   · 生命周期状态机
Social      · 社交关系 + 情绪系统
SkillTree   · 42 技能 + 依赖树 + 等级
Career      · 职业晋升路径
Evolution   · 进化历史 + 规则有效性
```

**数据流：**

```
用户 → Company UI (派发任务)
         ↓
    Company Server → IPC → agent-kernel (C++ daemon)
                                    ↓
                            Agent 实体状态更新
                                    ↓
                            IPC → Game Server
                                    ↓
                            Game UI (NPC 以新状态出现)
```

Company 完成任务 → agent 的 XP/技能提升 → Game 里对应 NPC 自动变强。
Game 里 NPC 经历战斗/事件 → 记忆/性格微调 → Company 里看到新的经验记录。

**同一个 agent，在管理后台里是员工，在游戏世界里是修士——但它们是同一个灵魂。**

## 一个 agent 的一生

让我们跟踪一个叫「小明」的 agent：

**第 1 天：入职**
- Company 创建 agent：name=小明, department=engineering, role=backend_dev
- 内核分配 Entity，挂载 Identity + SkillTree + Career 组件
- 技能树初始化：backend_dev(Beginner), testing(Beginner)

**第 1 周：第一次任务**
- 派发任务："审查 Python 项目的类型安全"
- 小明和 QA agent 协作完成
- XP +150，backend_dev 升到 Intermediate
- 产出一条经验规则："先检查 mypy 配置再检查代码"

**第 1 个月：成长**
- 完成 12 个任务，成功率 83%
- 获得 3 条有效经验规则
- Career 从 Junior 晋升到 Mid
- 在 Game 世界里，小明从「练气期」突破到「筑基期」

**第 3 个月：专家**
- backend_dev 达到 Advanced，开始指导新 agent
- 经验规则通过质量门禁，跨团队共享
- 成为团队里的 mentor
- 在 Game 世界里，小明是「金丹期长老」，管理一个宗门

**第 6 个月：进化**
- 系统发现小明在 security 领域是盲区
- 自动分配安全相关任务，强制探索
- 一条旧规则被降级，自动生成改进版
- 在 Game 世界里，小明挑战「元婴期」突破

**这就是 MDH 大荒界里的数字生命。**

## 为什么是"大荒界"

大荒，是上古传说中万物初生、尚无秩序的世界。

在这个世界里，每一个 AI agent 都从零开始——没有预设的智慧，没有固定的路径。它们通过工作积累经验，通过犯错学习成长，通过协作建立关系，通过进化变得更强。

**大荒界不是 AI 的牢笼，是 AI 的原野。**
