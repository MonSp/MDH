# 并行多Agent系统改造 - 需求文档

## 目标

将当前单LLM多角色扮演系统改造为真正的并行多Agent系统，实现各Agent的独立并行执行、独立API密钥管理、消息队列通信和水平扩展支持。

## 范围

本项目涉及以下核心模块的改造：
- DiscussionManager（讨论管理器）
- KeyManager（密钥管理器）
- MessageQueue（消息队列）
- AgentPool（Agent池管理器）

改造将保持现有功能不变，支持向后兼容现有API，并支持渐进式迁移。

## 功能要求

### 1. 并行执行引擎

**需求描述：** 系统应支持多个Agent的并行执行，替代当前的串行循环模式。

**当前问题：** 
- 当前系统在 `discussion_manager.py` 中使用串行循环依次调用每个角色（第67-100行）
- 每个Agent必须等待前一个Agent完成才能开始执行
- 讨论轮次时间与Agent数量成正比

**改进目标：**
- 使用 `asyncio.gather` 实现并行调用
- 支持并发控制和超时处理
- 讨论轮次时间减少50%以上

### 2. 独立API密钥管理

**需求描述：** 系统应支持为每个Agent角色配置独立的API密钥和rate limit。

**当前问题：**
- 当前系统在 `meeting_coordinator.py` 中所有Agent共享同一个provider和api_key（第182-212行）
- 无法为不同角色设置不同的rate limit
- 无法实现密钥轮换和故障隔离

**改进目标：**
- 创建KeyManager类，支持按角色配置独立的API密钥
- 提供密钥轮换机制
- 支持独立的rate limit管理

### 3. 消息队列系统

**需求描述：** 系统应通过消息队列进行异步消息传递，支持消息持久化和重试。

**当前问题：**
- 当前系统使用函数调用进行消息传递，不是真正的消息队列
- 消息无法持久化
- 缺乏重试机制

**改进目标：**
- 实现基于 `asyncio.Queue` 的内存消息队列
- 支持消息持久化到SQLite
- 提供重试机制和死信队列

### 4. 水平扩展支持

**需求描述：** 系统应支持动态创建和销毁Agent实例，无需重启服务。

**当前问题：**
- Agent实例在启动时创建，无法动态调整
- 无法实现负载均衡
- 缺乏健康检查机制

**改进目标：**
- 实现AgentPool类，支持动态创建和销毁Agent实例
- 提供负载均衡策略
- 实现健康检查和自动恢复

## 验收标准

### 1. 并行执行验收标准

**触发条件：** 当系统执行多Agent讨论时

**期望结果：** 
- 各Agent应能够并行执行
- 讨论轮次时间相比串行执行减少50%以上
- 系统应正确处理并发冲突和超时

### 2. 独立API密钥验收标准

**触发条件：** 当配置Agent时

**期望结果：**
- 系统应支持为每个Agent角色配置独立的API密钥
- 每个Agent应有独立的rate limit
- 密钥轮换应不影响正在进行的讨论

### 3. 消息队列验收标准

**触发条件：** 当Agent需要通信时

**期望结果：**
- 系统应通过消息队列进行异步消息传递
- 消息应支持持久化
- 失败的消息应自动重试

### 4. 水平扩展验收标准

**触发条件：** 当需要增加Agent实例时

**期望结果：**
- 系统应支持动态创建和销毁Agent实例
- 新实例应自动加入负载均衡池
- 系统应能检测和恢复不健康的实例

## 约束条件

1. **向后兼容：** 改造后的系统必须保持与现有API的兼容性
2. **渐进式迁移：** 支持逐步从串行模式迁移到并行模式
3. **性能可度量：** 性能提升必须可量化验证
4. **轻量级方案：** 优先使用内存队列，避免引入外部依赖（如Redis/RabbitMQ）

## 假设

1. 当前Python异步框架（asyncio）能够支持并行执行
2. LLM API支持并发调用
3. 现有代码结构允许模块化改造

## 风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 并行执行可能导致资源竞争 | 高 | 使用异步锁和队列控制并发度 |
| 独立API密钥管理复杂 | 中 | 提供统一的密钥管理接口 |
| 消息队列引入增加系统复杂度 | 中 | 先使用内存队列，后续可扩展为持久化队列 |
| 现有代码改造工作量大 | 中 | 采用渐进式迁移策略 |

## 成功标准

1. **性能提升：** 讨论轮次时间减少50%以上
2. **功能完整：** 所有现有功能正常工作
3. **可扩展性：** 支持动态增加Agent实例
4. **可靠性：** 消息传递成功率99.9%以上
