# F5: 未来方向与反方观点

## Findings

### [1] Anthropic 官方立场（2024-12）：最成功的 agent 实现普遍使用"简单、可组合的模式"而非复杂框架，且主张"更简单方案不足时"才引入多步 agentic 系统。
- quote: "Consistently, the most successful implementations use simple, composable patterns rather than complex frameworks." 及 "Start with simple prompts, optimize them with comprehensive evaluation, and add multi-step agentic systems only when simpler solutions fall short."
- url: https://www.anthropic.com/research/building-effective-agents
- source_type: primary
- published: 2024-12-19
- confidence: high

### [2] Anthropic 在同一文中首次将"agent-computer interface (ACI)"确立为核心原则，主张应像投入 HCI 一样投入 ACI（工具文档与测试），并区分 workflow（预定义代码路径）与 agent（模型动态自导）两类 agentic 系统。
- quote: "Carefully craft your agent-computer interface (ACI) through thorough tool documentation and testing." 及 "think about how much effort goes into human-computer interfaces (HCI), and plan to invest just as much effort in creating good agent-computer interfaces (ACI)."
- url: https://www.anthropic.com/research/building-effective-agents
- source_type: primary
- published: 2024-12-19
- confidence: high

### [3] ACI 作为研究范式最早由 SWE-agent（Princeton）以论文形式确立：把 LM agent 视为"一类新的终端用户"，需专门设计的软件接口；其自定义 ACI 显著提升编码/导航/测试能力（SWE-bench pass@1 12.5%）。
- quote: "LM agents represent a new category of end users with their own needs and abilities, and would benefit from specially-built interfaces to the software they use." 及 "SWE-agent's custom agent-computer interface (ACI) significantly enhances an agent's ability to create and edit code files, navigate entire repositories, and execute tests and other programs."
- url: https://arxiv.org/abs/2405.15793
- source_type: primary
- published: 2024-05-06
- confidence: high

### [4] Anthropic "Agent Skills"（2025-10，2025-12-18 发布为跨平台开放标准 agentskills.io）：以"文件夹+指令+脚本"打包领域知识，靠 progressive disclosure（渐进披露）按需加载，明确定位为"取代为每个用例定制碎片化 agent"。
- quote: "Instead of building fragmented, custom-designed agents for each use case, anyone can now specialize their agents with composable capabilities by capturing and sharing their procedural knowledge." 及 "We've published Agent Skills as an open standard for cross-platform portability. (December 18, 2025)"
- url: https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills
- source_type: primary
- published: 2025-10-16
- confidence: high

### [5] Anthropic 正式采纳"context engineering"为 prompt engineering 的接棒范式（2025-09），并将该术语的普及归因于 Andrej Karpathy（2025-06 推文）；核心论点是 context 是"注意力预算"约束下的有限资源（n² 注意力、context rot）。
- quote: "After a few years of prompt engineering being the focus of attention in applied AI, a new term has come to prominence: context engineering." 及 "Context, therefore, must be treated as a finite resource with diminishing marginal returns."（文中以链接 x.com/karpathy/status/1937902205765607626 标注该术语为 Karpathy 提出）
- url: https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- source_type: primary
- published: 2025-09-29
- confidence: high

### [6] Anthropic 将 multi-agent（sub-agent 架构）重新定义为一种"context 管理技术"而非组织模拟：三大长程上下文技术为 compaction、structured note-taking、multi-agent architectures，且业界正收敛到"agent = LLM 自主在循环中使用工具"这一最简定义。
- quote: "we've developed a few techniques that address these context pollution constraints directly: compaction, structured note-taking, and multi-agent architectures." 及 "we've gravitated towards a simple definition for agents: LLMs autonomously using tools in a loop."
- url: https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- source_type: primary
- published: 2025-09-29
- confidence: high

### [7] 反方实证：Berkeley 团队（Ion Stoica、Matei Zaharia、Joseph Gonzalez、Dan Klein 等）在 "Why Do Multi-Agent LLM Systems Fail?" 中给出 MAS 失败分类学 MAST——14 种失败模式、3 大类（system design / inter-agent misalignment / task verification），并指出 MAS 在流行基准上的收益常常微乎其微。
- quote: "their performance gains on popular benchmarks are often minimal." 及 "14 unique modes, clustered into 3 categories: (i) system design issues, (ii) inter-agent misalignment, and (iii) task verification."（MAST-Data：1600+ traces，7 个 MAS 框架，kappa=0.88）
- url: https://arxiv.org/abs/2503.13657
- source_type: primary
- published: 2025-03-17
- confidence: high

### [8] 替代方案研究（2026-01）：多 agent 系统可被"编译"为"单 agent + 技能选择"，以技能库取代 agent 间通信，显著降低 token/延迟且精度持平；但技能选择存在类人认知的"容量相变"（库规模超临界点后准确率骤降），分层路由可缓解。
- quote: "a multi-agent system can be compiled into an equivalent single-agent system, trading inter-agent communication for skill selection." 及 "selection accuracy remains stable up to a critical library size, then drops sharply, indicating a phase transition reminiscent of capacity limits in human cognition."
- url: https://arxiv.org/abs/2601.04748
- source_type: primary
- published: 2026-01-08
- confidence: high

### [9] 反方对反方（2025-12）：有研究主张单纯扩展单 agent 能力不会自动获得多 agent 智能，主张基础模型需"原生多 agent 智能"（41 个 LLM、7 个基准的实证），说明单 agent vs 多 agent 之争仍在进行。
- quote: "scaling single-agent performance alone does not automatically yield robust multi-agent intelligence." 及 "we argue that the next frontier is endowing FMs with native multi-agent intelligence."
- url: https://arxiv.org/abs/2512.08743
- source_type: primary
- published: 2025-12-09
- confidence: high

### [10] 2026-07 最新失败模式研究：LLM agent 之间"无法互相探索"，常表现出短视与极化交互导致次优协调与更高 regret（Multi-Agent Exploration 问题），提示"多智能体会议/讨论"类机制天然存在协调缺陷。
- quote: "modern LLM agents fail to do so, often exhibiting myopic and polarized interaction patterns that lead to suboptimal coordination and increased regret."
- url: https://arxiv.org/abs/2607.11250
- source_type: primary
- published: 2026-07-13
- confidence: high
