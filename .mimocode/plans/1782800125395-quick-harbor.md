# TS-Python 智能体桥接方案

## 目标
让前端 TS 创建的智能体实例和后端 Python 创建的 agentscope 智能体实例可以互相发送消息、协作完成任务。

## 约束
- 复用现有 WebSocket 连接（`ws://host:8765/ws`），新增消息类型
- 工具系统各自独立，不共享 ToolExecutor
- 不改变现有 Python 智能体的创建和运行方式
- 不改变现有 TS CommunicationBus 的内部机制

## 架构概览

```
┌─ 前端 TS ─────────────────────────────────────────┐
│                                                    │
│  AgentRegistry ←→ AgentCoordinator                 │
│       ↕ CommunicationBus                           │
│       ↕                                            │
│  WebSocketBridge (新增)                             │
│       ↕ WebSocket (复用现有连接)                    │
└────────────────────────────────────────────────────┘
                    ↕
┌─ 后端 Python ─────────────────────────────────────┐
│                                                    │
│  server.py ws_handler                              │
│       ↕                                            │
│  AgentBridge (新增)                                 │
│       ↕                                            │
│  MeetingSession + AgentPool (现有)                  │
│       ↕                                            │
│  agentscope Agent (现有)                            │
└────────────────────────────────────────────────────┘
```

## 核心设计

### 1. 智能体 ID 映射

| 侧 | ID 格式 | 示例 |
|---|---|---|
| TS | `crypto.randomUUID()` | `a1b2c3d4-e5f6-...` |
| Python | 固定角色字符串 | `agent-ceo`, `agent-executor` |

桥接层维护双向映射表：
```
TS_ID <-> Python_ID
"a1b2c3d4..." <-> "agent-executor"
```

Python 端为每个注册的 TS 智能体分配一个内部 ID（`ts-{uuid[:8]}`），在 MeetingSession 中以 `MeetingAgentInfo` 形式存在。

### 2. 新增 WebSocket 消息类型

#### TS → Python（3 个新消息）

| 消息类型 | 用途 | 关键字段 |
|---|---|---|
| `bridge_register_agent` | TS 智能体注册到 Python 端 | `tsAgentId, name, role, capabilities` |
| `bridge_unregister_agent` | TS 智能体注销 | `tsAgentId` |
| `bridge_message` | TS 智能体发消息给 Python 智能体 | `fromAgentId, toAgentId, payload` |

#### Python → TS（2 个新消息）

| 消息类型 | 用途 | 关键字段 |
|---|---|---|
| `bridge_agent_registered` | 注册确认 | `tsAgentId, pyAgentId` |
| `bridge_message` | Python 智能体发消息给 TS 智能体 | `fromAgentId, toAgentId, payload` |

### 3. 消息格式

```typescript
// bridge_register_agent (TS → Python)
{
  type: 'bridge_register_agent',
  tsAgentId: 'a1b2c3d4-...',
  name: 'My Coder Agent',
  role: 'executor',          // AgentRole 枚举值
  capabilities: ['code_generation', 'testing'],
  sequence_no: 42
}

// bridge_agent_registered (Python → TS)
{
  type: 'bridge_agent_registered',
  tsAgentId: 'a1b2c3d4-...',
  pyAgentId: 'ts-a1b2c3d4',  // Python 端分配的 ID
  success: true,
  sequence_no: 43
}

// bridge_message (双向)
{
  type: 'bridge_message',
  fromAgentId: 'a1b2c3d4-...',  // 发送方 ID（可以是 TS 或 Python ID）
  toAgentId: 'agent-executor',   // 接收方 ID（可以是 TS 或 Python ID）
  messageType: 'TaskAssignment', // 可选：TS MessageType 枚举值
  payload: { ... },              // 消息内容
  sequence_no: 44
}
```

### 4. 实现计划

#### Phase 1: TS 端 — WebSocketBridge 类

**新建文件**: `src/modules/webSocketBridge.ts`

```typescript
class WebSocketBridge {
  private wsRef: React.MutableRefObject<WebSocket | null>
  private agentRegistry: AgentRegistry
  private communicationBus: CommunicationBus
  private idMap: Map<string, string>  // tsId <-> pyId

  // 注册 TS 智能体到 Python 端
  registerAgent(agentId: string): void
  // 注销
  unregisterAgent(agentId: string): void
  // 发送消息到 Python 智能体
  sendMessage(fromId: string, toPyId: string, payload: any): void
  // 处理来自 Python 的 bridge 消息
  handleBridgeMessage(msg: any): void
  // 获取 Python 端的智能体 ID
  getPythonId(tsId: string): string | undefined
  // 获取 TS 端的智能体 ID
  getTsId(pyId: string): string | undefined
}
```

#### Phase 2: Python 端 — AgentBridge 类

**新建文件**: `backend/agent_bridge.py`

```python
class AgentBridge:
    def __init__(self, meeting_session, agent_pool):
        self._ts_agents: Dict[str, MeetingAgentInfo]  # pyId -> agent info
        self._id_map: Dict[str, str]  # tsId <-> pyId
        self._reverse_map: Dict[str, str]

    async def register_ts_agent(self, ts_agent_id, name, role, capabilities, send_fn):
        """注册 TS 智能体，创建 MeetingAgentInfo，返回 pyAgentId"""

    async def unregister_ts_agent(self, ts_agent_id, send_fn):
        """注销 TS 智能体"""

    async def route_message(self, from_id, to_id, payload, send_fn):
        """路由消息：如果是 Python 智能体则直接调用，如果是 TS 智能体则通过 WebSocket 发回"""

    def get_py_agent(self, agent_id):
        """获取 Python 端智能体（可能是原生的或 TS 注册的）"""
```

#### Phase 3: server.py 集成

在 `ws_handler` 的消息分发 switch 中添加 3 个新 case：

```python
elif msg_type == "bridge_register_agent":
    await agent_bridge.register_ts_agent(
        msg["tsAgentId"], msg["name"], msg["role"],
        msg.get("capabilities", []), session.send_and_buffer
    )
elif msg_type == "bridge_unregister_agent":
    await agent_bridge.unregister_ts_agent(msg["tsAgentId"], session.send_and_buffer)
elif msg_type == "bridge_message":
    await agent_bridge.route_message(
        msg["fromAgentId"], msg["toAgentId"],
        msg.get("payload", {}), session.send_and_buffer
    )
```

#### Phase 4: useMeetingSocket.ts 集成

在 WebSocket message handler 中添加 `bridge_agent_registered` 和 `bridge_message` 的处理：

```typescript
case 'bridge_agent_registered': {
  // 更新 ID 映射
  bridge.handleRegistration(msg.tsAgentId, msg.pyAgentId, msg.success)
  break
}
case 'bridge_message': {
  // 将消息注入 CommunicationBus
  bridge.handleBridgeMessage(msg)
  break
}
```

#### Phase 5: AgentRegistry 扩展

在 `AgentConfig` 中添加可选的 `remote` 标记：

```typescript
interface AgentConfig {
  // ... 现有字段
  remote?: boolean       // 是否为远程（Python 端）智能体
  pyAgentId?: string     // Python 端的 ID（注册后由 bridge 回填）
}
```

### 5. 消息路由逻辑

```
TS Agent A 想发消息给 Python Agent B:

1. A 调用 communicationBus.sendMessage(type, A.id, "agent-executor", payload)
2. CommunicationBus 尝试本地投递 → 找不到 "agent-executor" 的 handler
3. WebSocketBridge 监听到未投递的消息
4. Bridge 检查 idMap: "agent-executor" 不在 TS 注册表中 → 是 Python 智能体
5. Bridge 通过 WebSocket 发送 bridge_message
6. Python agent_bridge.route_message() 收到消息
7. 查找 MeetingSession 中的 "agent-executor" → 找到 agentscope Agent
8. 调用 agent.reply(Msg(...)) → LLM 处理
9. 响应通过 bridge_message 发回 TS
10. TS WebSocketBridge.handleBridgeMessage() 注入 CommunicationBus
11. A 的 handler 收到响应
```
