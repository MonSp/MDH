# V4.8 -> V4.9 迁移指引

**面向**: 外部 iframe 接入方 / bridge 调用方
**版本**: V4.9 (2026-06-01)
**目标**: 完成从 V4.8 到 V4.9 的协议收口迁移，并接入 P130-P132 新增结果字段

---

## 1. 为什么要迁

V4.9 的核心不是增加新命令，而是把 V4.8 仍处于“兼容保留”状态的协议面彻底收口，同时补齐 selector 上下文能力。迁移重点有四件事：

- **`selector_type` 物理移除**：调用方不再声明 CSS / XPath 类型，由宿主自动推断
- **`query_handle` 物理移除**：元素查询统一走 `query_target`
- **`handle_id` 执行桥接退出**：执行阶段只认 `target_ref`
- **结果上下文增强**：可直接消费 `match_count` / `match_summary` / `children` / `attributes`

---

## 2. 迁移重点速查

| 主题 | V4.8 | V4.9 |
|---|---|---|
| selector 类型声明 | `selector_type` 仍可能出现 | **字段已移除，自动推断 CSS / XPath** |
| 元素查询命令 | `query_target` / `query_handle` 并存迁移期 | **仅保留 `query_target`** |
| 执行身份 | `target_ref` 是主路径，仍见到 `handle_id` 兼容桥接 | **执行阶段仅应使用 `target_ref`** |
| selector 结果 | 主要返回单一命中 | **可返回 `match_count` / `match_summary` / `children` / `attributes`** |

---

## 3. `selector_type` 已移除

### 总原则

- 不再传 `selector_type`
- 让宿主根据 `selector` 文本自动推断定位类型

### 自动推断规则

- `//` 或 `(//` 开头 -> XPath
- `/` 开头 -> XPath
- 其余 -> CSS

### 推荐写法

```json
{
  "command": "resolve_selector",
  "payload": {
    "selector": "//button[@type='submit']"
  }
}
```

### 不再允许的写法

```json
{
  "command": "resolve_selector",
  "payload": {
    "selector": "//button[@type='submit']",
    "selector_type": "xpath"
  }
}
```

---

## 4. `query_handle` -> `query_target`

### 总原则

- V4.9 只保留 `query_target`
- 若需要查询元素状态，先通过 `resolve_selector` 获得 `target_ref`，再调用 `query_target`

### 推荐调用链

```json
{
  "command": "resolve_selector",
  "payload": {
    "selector": "#submit"
  }
}
```

```json
{
  "command": "query_target",
  "payload": {
    "target_ref": "ref:12345:7"
  }
}
```

### 不再允许的写法

```json
{
  "command": "query_handle",
  "payload": {
    "handle_id": "legacy-submit"
  }
}
```

---

## 5. `handle_id` -> `target_ref`

### 总原则

- 执行阶段只把 `target_ref` 当权威元素身份
- `handle_id` 在 V4.9 中仍可能以兼容元数据形式出现在部分结果中，但不应再进入新的 command payload
- 若你的代码同时拿到 `handle_id` 与 `target_ref`，执行阶段只透传 `target_ref`

### 推荐写法

```json
{
  "command": "click_button",
  "payload": {
    "target_ref": "ref:12345:7"
  }
}
```

### 不再推荐的写法

```json
{
  "command": "click_button",
  "payload": {
    "handle_id": "legacy-submit"
  }
}
```

### 适用范围

- `click_button`
- `input_text`
- `wait_for_element`
- `screenshot_element`
- `scroll_into_view`
- `hover`
- 以及所有以元素执行为中心的后续 bridge 扩展调用

---

## 6. 新增结果字段如何接入

### 多匹配感知

`resolve_selector` 现在可返回：

- `match_count`
- `matched_index`
- `match_summary`

推荐用法：当 `match_count > 1` 时，先读取 `match_summary` 做二次决策，再使用其中的 `target_ref` 继续查询或执行。

### 子元素列表

`resolve_selector` / `query_target` 现在可返回：

- `children`
- `child_count`

推荐用法：先读取一级子元素，按需逐层深入，而不是一次性递归展开整棵树。

### 属性返回

`resolve_selector` / `query_target` 现在可返回：

- `attributes`

推荐用法：优先消费 `href`、`class`、`id`、`data-*`、`aria-*` 等属性，而不是回退到字符串猜测。

---

## 7. 接入方行动建议

1. 删除所有 `selector_type` 字段写入点
2. 删除所有 `query_handle` 调用点，统一改成 `query_target`
3. 清理所有把 `handle_id` 作为执行输入的调用点
4. 在 selector 结果消费侧补入 `match_count` / `match_summary` 处理分支
5. 在 target 查询消费侧补入 `children` / `child_count` / `attributes`

---

## 8. 回归验证建议

- 协议收口：`SelectorTypeAutoDetect`、`QueryTargetOnly`
- `target_ref` 权威路径：`TargetRefOnlyNoHandleBridge`、`HandleIdFieldIgnored`
- 多匹配感知：`ResolveSelectorMultiMatch`、`ResolveSelectorXPathMultiMatch`
- 子元素列表：`ResolveSelectorChildren`、`QueryTargetChildren`
- 属性修复：`ResolveSelectorAttributes`、`QueryTargetAttributes`
