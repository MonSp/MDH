# AI Automation Bridge 对接协议

**版本**: V4.8 协议版
**协议版本**: `1.3`
**面向**: 前端开发同事（外部 iframe 内系统接入方）
**用途**: 直接对接浏览器宿主与 iframe 内业务系统的消息协议
**创建日期**: 2026-05-11
**最后更新**: 2026-05-28
**维护者**: AI Automation Team

---

## 1. 协议总览

### 1.1 消息方向

- iframe -> 宿主：发送 `request`
- 宿主 -> iframe：返回 `response`
- 宿主 -> iframe：主动推送 `event`

### 1.2 元素定位约定

```text
target_ref > selector
```

- `target_ref`：首选元素引用，适合后续连续操作
- `selector`：适合首次定位，通过 `resolve_selector` 转换为 `target_ref`

### 1.3 最常用调用链

```typescript
const resolved = await bridge.call('resolve_selector', {
  selector: '#submit',
  selector_type: 'css',
});

await bridge.call('click_button', {
  target_ref: resolved.target_ref,
});
```

### 1.4 V4.8 关键变更速查

| 变更项 | V4.7 | V4.8 |
|---|---|---|
| `navigate` 完成语义 | 发起跳转即返回 | **等待页面原生加载完成** |
| `execute_plan` target 传递 | 每步需自行传 `target_ref` | **`planTargetContext` 自动续接** |
| `selector_type` 废弃状态 | console.warn 警告 | **仍可用但强烈建议迁移** |
| 页面变化后 target 失效 | 部分规则缺失 | **`PAGE_CHANGED` 触发完整失效** |

## 2. 版本协商 (Version Negotiation)

### 2.1 ProtocolVersionInfo

```typescript
export interface ProtocolVersionInfo {
  protocol_version: string;
  min_supported_version: string;
  deprecated_fields: string[];
  deprecation_schedule: Record<string, string>;
}
```

| 字段 | 类型 | 说明 | 示例 |
|---|---|---|---|
| `protocol_version` | `string` | 当前端使用的协议版本 | `"4.8"` |
| `min_supported_version` | `string` | 本端最低支持的对端版本 | `"4.5"` |
| `deprecated_fields` | `string[]` | 已标记废弃但尚未移除的字段 | `["handle_id", "selector_type"]` |
| `deprecation_schedule` | `Record<string, string>` | 废弃字段的计划移除版本 | `{"handle_id": "5.0", "selector_type": "4.9"}` |

### 2.2 协商流程

**步骤 1** — Host 在 handshake 成功后发送 `manifest_push` 事件，携带 `ProtocolVersionInfo`：

```typescript
{
  // ... ToolManifest 字段 ...
  protocol_version: "4.8",
  min_supported_version: "4.5",
  deprecated_fields: ["handle_id", "selector_type"],
  deprecation_schedule: { "handle_id": "5.0", "selector_type": "4.9" },
  tools: [...],
  page_metadata: {...}
}
```

**步骤 2** — iframe 端校验：

```typescript
if (manifest.min_supported_version > iframeProtocolVersion) {
  closeConnection('VERSION_INCOMPATIBLE');
}
```

**步骤 3** — iframe 端 handshake 请求：

```typescript
{
  id: 'hs_1',
  type: 'request',
  command: 'handshake',
  payload: {
    protocol_version: "4.8",
    min_supported_version: "4.5",
  },
  timestamp: Date.now()
}
```

**步骤 4** — Host 反向校验，版本不兼容时返回 `VERSION_INCOMPATIBLE` 错误。

**步骤 5** — 版本兼容时正常建立连接。

### 2.3 版本兼容性矩阵

| Host 版本 | 支持的 iframe 最低版本 | `handle_id` | `selector_type` |
|---|---|---|---|
| 4.5 | 4.5 | ✓ | ✓ |
| 4.6 | 4.5 | ✓ (deprecated) | ✓ (deprecated) |
| 4.7 | 4.5 | ⚠ (console.warn) | ⚠ (console.warn) |
| **4.8** | **4.5** | **⚠ (console.warn)** | **⚠ (console.warn)** |
| 4.9 | 4.5 | ⚠ (console.warn) | ❌ (removed) |
| 5.0 | 4.5 | ❌ (removed) | ❌ |

> **V4.8 说明**：原计划 V4.8 移除 `selector_type`，但为给接入方更多迁移时间，V4.8 仅保留 console.warn 警告，移除推迟到 V4.9。

## 3. 通用消息结构

```typescript
export enum MessageType {
  REQUEST = 'request',
  RESPONSE = 'response',
  EVENT = 'event',
}

export interface BridgeError {
  code: ErrorCode;
  message: string;
  detail?: any;
}

export interface Message {
  id: string;
  type: MessageType;
  command?: string;
  payload?: any;
  error?: BridgeError;
  timestamp: number;
  manifest_version?: string;
}
```

### 3.1 请求示例

```typescript
window.parent.postMessage({
  id: 'req_1',
  type: 'request',
  command: 'navigate',
  payload: {url: 'https://example.com'},
  timestamp: Date.now(),
}, window.location.origin);
```

### 3.2 响应示例

```typescript
{
  id: 'req_1',
  type: 'response',
  command: 'navigate',
  payload: {
    success: true,
    url: 'https://example.com',
  },
  timestamp: Date.now(),
}
```

**V4.8 关键变更**：`navigate` 的完成条件从"已发起跳转"变为"**页面原生加载完成（DidFinishLoad）**"。这意味着：

### 9.2 `execute_plan` ⚠️ V4.8 重要变更

**V4.8 关键变更**：

1. **`planTargetContext` 自动续接**：当 `execute_plan` 的步骤中包含 `resolve_selector` 成功后，返回的 `target_ref` 会自动存入 plan-scope target context。后续的 target consumer 步骤（`click_button`、`wait_for_element`、`input_text`、`scroll_into_view`、`hover`、`screenshot_element`）如果自身 payload 中没有 `target_ref` 也没有 `selector`，会自动继承这个 context 中的 `target_ref`。

2. **target context 失效规则**：
   - `navigate` / `switch_tab` / `create_tab` / `close_tab` 步骤执行后，target context 自动清除
   - 步骤返回 `TARGET_STALE` 错误时，target context 自动清除
   - `manifest_stale` 时，target context 自动清除
   - 收到 `page_changed` 事件时，target context 自动清除

3. **`navigate` 步骤等待原生加载**：`navigate` 步骤会等待页面 `DidFinishLoad` 事件后再继续下一步，超时 30 秒。

```typescript
export type StepRecovery =
```

#### 9.2.1 `planTargetContext` 使用示例

```typescript
// 6 步计划：resolve → click → resolve → click → resolve → click
// 第 2、4、6 步的 click_button 不需要传 target_ref，自动继承上一步 resolve 的结果
window.parent.postMessage({
  id: 'plan_1',
  type: 'request',
  command: 'execute_plan',
  payload: {
    manifest_version: cachedManifestVersion,
    steps: [
      { command: 'resolve_selector', payload: { selector: '#main-btn', selector_type: 'css' } },
      { command: 'click_button', payload: {} },  // 自动使用 #main-btn 的 target_ref
      { command: 'resolve_selector', payload: { selector: '#shadow-btn', selector_type: 'css' } },
      { command: 'click_button', payload: {} },  // 自动使用 #shadow-btn 的 target_ref
      { command: 'resolve_selector', payload: { selector: '#frame-btn', selector_type: 'css' } },
      { command: 'click_button', payload: {} },  // 自动使用 #frame-btn 的 target_ref
    ],
    stop_on_error: true,
  },
  timestamp: Date.now(),
}, window.location.origin);
```

#### 9.2.2 target context 失效示例

```typescript
// navigate 后旧 target_ref 自动失效
```


## 11. SSO / 登录平台跳转保护

### 11.1 背景

bridge iframe 默认只允许加载 `chrome://ai-automation-side-panel.top-chrome` 来源的内容。当 iframe 内的业务系统需要跳转到 SSO / 身份提供商进行登录认证时，CSP 会阻止加载非默认 origin 的内容，导致登录流程无法完成、握手断开。

### 11.2 解决方案

通过命令行开关 `--company-chat-extra-allowed-origins` 指定额外允许的 origin 列表：

```bash
# 单个 origin
--company-chat-extra-allowed-origins=https://sso.company.com

# 多个 origin，逗号分隔
--company-chat-extra-allowed-origins=https://sso.company.com,https://login.company.com,https://idp.partner.com
```

### 11.3 工作原理

1. **启动时解析**：`GetCompanyChatHostRuntimeConfig()` 读取命令行开关，按逗号拆分 origin 列表，校验每个 origin 必须是合法的 HTTP/HTTPS URL
2. **CSP 指令注入**：`BuildIframeDirective()` 将 extra origins 追加到宿主页面的 CSP `frame-src` / `child-src` 指令中，使 iframe 可以加载这些 origin 的内容
3. **前端透传**：extra origins 通过 WebUI 数据 `companyChatExtraAllowedOrigins` 传递给前端，前端可用于判断当前跳转是否在允许范围内

### 11.4 典型接入流程

```text
1. 启动 Chrome 时加参数：
   --company-chat-extra-allowed-origins=https://sso.mycompany.com

2. bridge iframe 内的业务系统发起登录：
   iframe → 跳转到 https://sso.mycompany.com/login?redirect=...

3. 用户在 SSO 页面完成认证：
   SSO → 重定向回 iframe 原始 URL（携带 token）

4. iframe 重新加载，自动重新握手：
   iframe → handshake → manifest_push → 恢复正常工作流
```

### 11.5 注意事项

- extra origins 只影响 CSP 指令，不影响 `postMessage` 的 origin 校验（`postMessage` 仍以 `allowed_origin` 为准）
- 校验不通过的 origin（非 HTTP/HTTPS、格式非法）会被静默忽略并输出 WARNING 日志
- 生产部署时应通过企业管理策略（Policy）配置此开关，避免在命令行明文暴露 SSO 地址

## 12. 最小接入建议

1. 初始化后先监听 `event`
2. 收到 `manifest_push` / `manifest_update` 后缓存 `manifest_version`
3. 在 `handshake` 请求中提供 `protocol_version` 和 `min_supported_version`
4. 需要稳定操作同一元素时，先调 `resolve_selector`，后续一律使用 `target_ref`
5. **V4.8**：在 `execute_plan` 中，`resolve_selector` 后的 target consumer 步骤可省略 `target_ref`，由 `planTargetContext` 自动续接
6. **V4.8**：`navigate` 步骤已自动等待页面加载完成，无需额外 `wait`
7. **V4.8**：页面切换（`navigate` / `switch_tab` / `create_tab` / `close_tab`）后，旧 `target_ref` 自动失效，需重新 `resolve_selector`
8. 涉及页面语义工具时，优先使用 `discover_tools` 返回的 `target_ref`
9. 收到 `confirm_required` 时，必须回 `confirm_response`
10. 机械恢复型失败可在 step 设置 `recovery` + `max_retries`
11. **迁移提醒**：`selector_type` 和 `handle_id` 仍可用但已废弃，新代码应优先使用 `target_ref`

## 13. 与 V4.7 的完整差异

| 类别 | V4.7 | V4.8 |
|---|---|---|
| 协议版本 | 1.2 | 1.3 |
| `navigate` 完成语义 | 发起跳转即返回 | 等待 `DidFinishLoad`，30s 超时 |
| `execute_plan` target 传递 | 每步自行传 `target_ref` | `planTargetContext` 自动续接 |
| target context 失效 | 部分规则 | `navigate` / `switch_tab` / `create_tab` / `close_tab` / `TARGET_STALE` / `manifest_stale` / `page_changed` 全覆盖 |
| `selector_type` 废弃 | console.warn | console.warn（移除推迟到 V4.9） |
| `handle_id` 废弃 | console.warn | console.warn（移除推迟到 V5.0） |
| JS 注入 | 7 条 `LEGACY_FALLBACK` 路径 | 全部 native 替代，`LEGACY_FALLBACK` 计数 = 0 |
| 安全校验 | `ValidateActionSecurity` 始终返回 true | 基于 `ExecutionPolicy` 实际判断 URL 白名单 |
