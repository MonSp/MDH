## 新增 (Added)

### SSO / 登录平台跳转保护
- `--company-chat-extra-allowed-origins` 命令行开关：允许 bridge iframe 跳转到额外的 SSO / 身份提供商 origin，解决 iframe 登录流程中 CSP 阻止导致握手断开的问题
- extra origins 通过 CSP 指令注入宿主页面，并透传给前端（`companyChatExtraAllowedOrigins`）
- 典型场景：iframe 内业务系统需要 SSO 认证时，配置 `--company-chat-extra-allowed-origins=https://sso.company.com`，iframe 可正常跳转到 SSO 页面完成认证后重新握手

## 变更 (Changed)

### 核心执行路径真实化 (P113-P119)
- `StepExecutionHandler` structured step 主链从 stub 收束到真实执行路径，`click` / `wait_for_element` / `input_text` / `scroll_element_into_view` 均有端到端守护
- `ContentHandler` 剩余 `LEGACY_FALLBACK` JS 注入路径已完成 native 替代，自诊断指标 `AIAutomation.AntiDetection.JsInjectionCount` 可用于确认 `LEGACY_FALLBACK` 分桶为 0
- `VisualHelper::CompareScreenshots` 以像素级 diff 守护视觉差异，不再依赖 base64 长度推断
- Domain 命令执行入口以 `target_ref` 为权威身份，专项 browser tests 已覆盖 `search` / `login` / `fill_form` / `filter_select` / `paginate` / `extract_list`
- `TaskExecutor::ValidateActionSecurity` 与确认流替代旧 stub，具备真实 URL / policy 判断
- bridge `execute_plan` 的 `navigate` 改为等待原生加载完成，并在页面变化后主动失效 plan-scope target context

## 兼容性说明

- `target_ref` 现在是所有高频执行路径的权威身份，接入方不应再以 `handle_id` 作为执行输入
- 兼容期内，部分发现/清单元数据仍可能包含 legacy `handle_id` 信息；这不应再被新的执行代码消费
- `chrome://histograms` 中若 `AIAutomation.AntiDetection.JsInjectionCount` 的 `LEGACY_FALLBACK` 分桶非 0，说明仍存在未收敛的旧路径
