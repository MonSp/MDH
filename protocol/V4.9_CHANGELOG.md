## 变更 (Changed)

### 协议收口 (P122-P124)
- `selector_type` 已从 V4.9 命令面移除，`resolve_selector` 改为自动推断 CSS / XPath
- `query_handle` alias 已退出 V4.9 协议面，统一收敛到 `query_target`
- 执行阶段继续以 `target_ref` 为权威元素身份；`handle_id` 仅保留兼容期元数据和废弃告警语义，不再作为 bridge 执行桥接入口

### 遗留清理 (P125-P127)
- `DomSnapshotter` 已完成重命名为 `AxSnapshotCache`，相关实现、单测与日志前缀统一收口
- `ComplexTaskOrchestrator` / link stub / content-browser 遗留路径按 V4.9 路线图完成收束，P128 以回归矩阵守护整体稳定性

### V4.9 封版口径 (P129)
- P129 不新增命令；职责是把 P122-P132 的既有实现、迁移信息、协议边界、回归结论和编译结果整理为可交付版本包
- V4.9 对外说明从“协议收口 + 遗留清除”扩展为“协议收口 + 遗留清除 + selector 上下文增强”

## 移除 (Removed)

### `selector_type`
- 调用方不再传 `selector_type`
- 自动推断规则：
  - `//` 或 `(//` 开头 -> XPath
  - `/` 开头 -> XPath
  - 其余 -> CSS

### `query_handle`
- `query_handle` 不再作为独立 bridge 命令存在
- 所有查询类调用应改用 `query_target`

### `handle_id` 执行桥接
- V4.9 不再支持把 `handle_id` 作为执行阶段的桥接身份使用
- 调用方应直接携带 `target_ref`

## 兼容性说明

- `target_ref` 是 V4.9 的权威元素身份；新的执行代码不应再以 `handle_id` 作为输入
- 兼容期内，部分返回结果和 manifest 元数据仍可能出现 `handle_id`，仅用于过渡观察，不应作为新逻辑依赖
- `selector_type` 已移除；若历史调用仍传入，接入方应在自身侧删除该字段
- `query_target` 在 V4.9 中承担元素查询与上下文扩展职责；接入方应围绕它消费 `attributes` / `children` 等新字段
