## 1. 协议总览

AI Automation Bridge 是浏览器宿主与 iframe 内业务系统之间的 postMessage 通信协议。浏览器不监听任何外部端口，所有交互均通过 `postMessage` 完成。

### 1.1 消息方向

| 方向 | 说明 |
|---|---|
| iframe → 宿主 | 发送 `request`，触发命令执行 |
| 宿主 → iframe | 返回 `response`，携带执行结果或错误 |
| 宿主 → iframe | 主动推送 `event`，通知页面变化、计划进度等 |

### 1.2 元素定位优先级

```text
target_ref  >  selector  >  handle_id（仅兼容元数据，不应用于新代码）
```

- `target_ref`：权威元素引用，由 `resolve_selector` 或 `query_target` 返回，适合后续连续操作
- `selector`：CSS 选择器或 XPath 表达式，首次定位使用，宿主自动推断类型
- `handle_id`：V4.9 中仅作为兼容期元数据出现，不应作为执行输入

### 1.3 典型调用链

```typescript
// 1. 定位元素，获取 target_ref 和上下文
const resolved = await bridge.call('resolve_selector', {
  selector: '#submit',
  include_match_summary: true,
  include_children: true,
});

// 2. 使用 target_ref 执行操作
await bridge.call('click_button', {
  target_ref: resolved.target_ref,
});

// 3. 查询元素最新状态
const detail = await bridge.call('query_target', {
  target_ref: resolved.target_ref,
});
```

## 2. 消息信封

所有消息均使用统一信封结构：

```typescript
export interface Message {
  id: string;                        // UUID，用于 request-response 配对
  type: MessageType;                 // 消息类型
  command?: BridgeCommand | string;  // 命令名（request/response 时必填）
  payload?: any;                     // 请求载荷或响应结果
  error?: BridgeError;               // 错误信息（仅 response 且失败时）
  timestamp: number;                 // 毫秒时间戳
  manifest_version?: string;         // 工具清单版本
}

export enum MessageType {
  REQUEST = 'request',
  RESPONSE = 'response',
  EVENT = 'event',
}

export interface BridgeError {
  code: ErrorCode;
  message: string;
  detail?: any;
}
```

### 2.1 Request 示例

```json
{
  "id": "a1b2c3d4-...",
  "type": "request",
  "command": "click_button",
  "payload": { "target_ref": "ref:12345:7" },
  "timestamp": 1717200000000
}
```

### 2.2 Response 示例（成功）

```json
{
  "id": "a1b2c3d4-...",
  "type": "response",
  "command": "click_button",
  "payload": { "clicked": true, "method": "native_event" },
  "timestamp": 1717200000100
}
```

```json

  "id": "a1b2c3d4-...",
```

### 5.5 元素定位与查询

#### `resolve_selector`

通过 CSS 选择器或 XPath 定位元素，返回 `target_ref` 和上下文信息。**这是元素定位的核心命令。**

```typescript
export interface ResolveSelectorPayload {
  selector: string;              // CSS 选择器或 XPath 表达式
  include_match_summary?: boolean;  // 默认 false
  include_children?: boolean;       // 默认 false
}
```

**自动推断规则**（无需指定类型）：

| selector 格式 | 推断结果 |
|---|---|
| `//` 或 `(//` 开头 | XPath |
| `/` 开头（非 `//`） | XPath（绝对路径） |
| 其余 | CSS |

```typescript
export interface ResolveSelectorResult {
  found: boolean;
  target_ref?: string;           // 后续执行的权威元素身份
  handle_id?: string;            // @deprecated
  descriptor?: TargetDescriptor;
  resolution_source?: string;    // css | xpath
  error_code?: string;           // ELEMENT_NOT_FOUND | INVALID_SELECTOR
  role?: string;
  name?: string;
  bounding_box?: BoundingBox;
  is_visible?: boolean;
  is_interactable?: boolean;
  inner_text?: string;
  tag_name?: string;
  attributes?: Record<string, string>;  // 元素的真实 HTML 属性
  match_count?: number;          // 总匹配数（始终返回）
  matched_index?: number;        // 当前主返回项在结果集中的索引（0-based）
  match_summary?: MatchSummaryEntry[];  // 仅 include_match_summary=true 时返回
  child_count?: number;          // 直接子元素总数
  children?: ChildDescriptor[];  // 仅 include_children=true 时返回
}
```

**返回语义**：

- `match_count` 始终返回（成本极低），即使 `include_match_summary=false`
- `match_summary` 仅在 `include_match_summary=true` 且 `match_count > 1` 时返回
- `children` 仅在 `include_children=true` 时返回，每个子元素的 `target_ref` 可直接复用
- `attributes` 包含元素所有 HTML 属性（`id`、`class`、`href`、`data-*`、`aria-*` 等），单个值超 200 字符截断，总数超 50 丢弃

#### `query_target`

通过 `target_ref` 查询元素当前状态。

```typescript
export interface QueryTargetPayload {
  target_ref: string;
}

export interface QueryTargetResult {
  found: boolean;
  target_ref?: string;
  handle_id?: string;            // @deprecated
  role?: string;
  name?: string;
  bounding_box?: BoundingBox;
  is_visible?: boolean;
  is_interactable?: boolean;
  descriptor?: TargetDescriptor;
  attributes?: Record<string, string>;
  error_code?: string;
  error_message?: string;
  descriptor_version?: string;
  child_count?: number;
  children?: ChildDescriptor[];
}
```

**使用建议**：
- 先 `resolve_selector` 获取 `target_ref`，再 `query_target` 查询最新状态
- `children` 返回的是实时查询结果（非缓存），适合渐进式 DOM 探索
- `attributes` 返回缓存属性，由 `resolve_selector` 首次采集时填充

## 6. 错误码

### 6.1 桥接级错误码（ErrorCode）

用于 `BridgeError.code`，表示消息级错误：

| 错误码 | 说明 |
|---|---|
| `CMD_NOT_FOUND` | 命令不存在 |
| `EXEC_ERROR` | 执行过程中出错 |
| `TIMEOUT` | 命令执行超时 |
| `INVALID_ORIGIN` | iframe 来源不在白名单 |
| `PROTOCOL_ERROR` | 消息格式或协议版本不兼容 |
| `MANIFEST_STALE` | 工具清单已过期，需要重新 discover |
| `TARGET_STALE` | 元素引用已失效，需要重新 resolve |
| `CANCELLED` | 命令被取消 |
| `ERR_NOT_IMPLEMENTED` | 命令未实现 |
| `MISSING_TARGET_REF` | 缺少必需的 target_ref |
| `NO_ACTIVE_PLAN` | 没有活跃的计划可操作 |
| `VERSION_INCOMPATIBLE` | 协议版本不兼容 |

用于计划步骤执行失败时的细分错误：

| 错误码 | 说明 |
|---|---|

| `PERMISSION_DENIED` | 权限不足 |

| `UNKNOWN_COMMAND` | 步骤中包含未知命令 |
| `EXECUTION_ERROR` | 通用执行错误 |
| `MANIFEST_STALE` | 清单过期 |
| `TARGET_STALE` | 目标引用过期 |
| `TIMEOUT` | 步骤超时 |

| 错误码 | 说明 |

## 8. 工具清单（Manifest）

宿主通过 `manifest_push` / `manifest_update` 向 iframe 推送当前页面可用的工具清单。

### 8.1 ManifestToolEntry 完整结构

```typescript
export interface ManifestToolEntry {
  name: string;                  // 命令名，如 "click_button"
  description: string;           // 人类可读描述
  parameters: Record<string, any>;  // JSON Schema 格式的参数定义
  risk: ManifestToolRisk;        // low | medium | high
  handle_id?: string;            // @deprecated
  fields?: Array<{
    name: string;
    type: string;
    required?: boolean;
    handle_id?: string;          // @deprecated
  }>;
  semantic?: SemanticAnnotation; // 语义标注（动作类型、风险、意图等）
}
```

### 8.2 清单版本

清单通过 `manifest_version` 字段标识版本。当宿主检测到页面变化导致清单过期时，会推送新的 `manifest_push`，此时旧清单中的 `target_ref` 可能已失效。

## 9. 安全边界

- **Bridge-only 通信**：浏览器不监听任何外部端口（无 HTTP/WebSocket 服务器），所有通信仅通过 `postMessage`
- **来源校验**：iframe 来源必须在白名单内，否则返回 `INVALID_ORIGIN`
- **确认流**：`risk: 'high'` 的操作会触发 `confirm_required` 事件，需 iframe 回复 `confirm_response`
- **CSP 策略**：`child-src` 仅允许同源测试页和已配置的外部域名
- **SSO 白名单**：通过 `--company-chat-extra-allowed-origins` 开关支持 SSO 跳转 origin

## 10. 废弃策略

### 10.1 三阶段废弃周期

1. **标注**：字段标记 `@deprecated`，仍正常工作
2. **警告**：宿主输出 `console.warn`，字段仍正常工作
3. **移除**：字段从协议面物理删除

### 10.2 当前状态

| 字段 | V4.7 | V4.8 | V4.9 | V5.0 |
|---|---|---|---|---|
| `selector_type` | 标注 | 警告 | **已移除** | — |
| `query_handle` | 标注 | 警告 | **已移除** | — |
| `handle_id` | 标注 | 警告 | ⚠ deprecated metadata | 计划移除 |

### 10.3 自动推断（替代 selector_type）

宿主根据 `selector` 文本自动推断定位类型：

```text
selector 以 "//" 或 "(//" 开头  →  XPath
selector 以 "/" 开头（非 "//"） →  XPath（绝对路径）
其余                             →  CSS
```

调用方无需、也不应再传递 `selector_type`。

## 11. 错误处理建议

1. **始终检查 `found` 字段**：`resolve_selector` 和 `query_target` 返回的 `found: false` 表示元素未找到，此时 `target_ref` 为空
2. **处理 `TARGET_STALE`**：页面导航或 DOM 大量变化后，之前获取的 `target_ref` 可能失效，需重新 `resolve_selector`
3. **处理 `MANIFEST_STALE`**：收到此错误时应调用 `discover_tools` 刷新清单
4. **检查 `match_count`**：当 `match_count > 1` 时，应通过 `match_summary` 确认操作的是正确元素
5. **渐进式 DOM 探索**：使用 `include_children: true` 获取一级子元素，通过 `child_count` 判断是否需要继续深入，避免一次性递归整棵树
